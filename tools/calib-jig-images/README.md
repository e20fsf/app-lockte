# calib-jig-images — ส่งรูป JIG ของแบบตรวจออกจาก Access เดิม (ตั๋ว #200)

รูป JIG ในรายงาน RPT-05 (23 ใบ) และ RPT-06 (19 ใบ) ของ `สอบเทียบ.accdb` เป็นกรอบ OLE (Word.Document) ที่ฝัง metafile (EMF) ไว้
เครื่องมือนี้อ่านนิยามรายงานที่ส่งออกเป็นข้อความ (`source/_extract/สอบเทียบ/reports/*.txt`) หากรอบ OLE ที่ใหญ่ที่สุดของแต่ละรายงาน
ดึง EMF ออกมาวาดเป็น PNG (ต้องรันบน Windows — ใช้ GDI+)

```bash
dotnet run --project tools/calib-jig-images -- "<source>/_extract/สอบเทียบ/reports" "<โฟลเดอร์นอก repo>/jig-images"
```

ผลลัพธ์ในโฟลเดอร์ปลายทาง
- `images/<hash8>.png` — หนึ่งไฟล์ต่อรูปที่ไม่ซ้ำ (ทดสอบกับไฟล์จริง: 42 รายงาน → 7 รูปที่ไม่ซ้ำ)
- `mapping.csv` — `type,model,report,image` (ชนิดแบบ ZeroCheck/Grinding, รุ่นตามปุ่มใน SCR-05, ชื่อรายงานเดิม, ไฟล์รูป)
- `summary.txt` — จำนวนที่ส่งออก/ขาด (ไม่มีข้อมูลบุคคล); exit code 1 ถ้ามีรายงานที่ไม่มีรูป

**ห้าม commit รูปและโฟลเดอร์ปลายทางเข้า repo** (repo เป็น public — Q-28 ข้อ 1) ใช้ `.gitignore` ของโฟลเดอร์นอก repo หรือวางไว้นอก working tree

## โหลดเข้าแอป
`JigImageRegistry.ImportFolderAsync(<โฟลเดอร์>)` (service ของ module `calib`) อ่าน `mapping.csv` + `images/` เก็บรูปเป็นข้อมูลของแอป (ตาราง `calib.JigImages`,
รูปเดียวกันเก็บชุดเดียว) และคืนรายงาน: จำนวนที่โหลด, แถวที่ไม่พบแบบ, ไฟล์ที่มีปัญหา, แบบที่ยังไม่มีรูป · ตั๋ว #209 ต่อเข้ากับเครื่องมือย้ายข้อมูล (`Lockte.Migration`)
QA เปลี่ยนรูปหรือเอารูปออกได้จากหน้า "แก้ไขแบบตรวจ JIG" · แบบที่ไม่มีรูปพิมพ์ได้ (กรอบว่าง) และหน้าแก้ไขเตือนว่าแบบไหนขาดรูป

## ข้อสังเกต
รูปที่ส่งออกเป็นภาพเส้นของ JIG; ป้ายจุด P1…P6 ของแบบเดิมเป็นกล่องข้อความแยกในรายงาน ไม่ได้อยู่ในรูป — ตั๋ว #207/#208 วางป้ายเองตามตัวอย่างพิมพ์
