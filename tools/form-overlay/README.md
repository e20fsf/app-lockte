# ตรวจรับเอกสารระดับ A — วาง PDF ซ้อนตัวอย่างเดิม

เกณฑ์ #40: เอกสารระดับ A พิมพ์จากข้อมูลชุดเดียวกับตัวอย่างของ Access แล้ววางซ้อนกัน ตำแหน่งคลาด ≤ ~2 มม. แล้ว HR เซ็นรับรายเอกสาร

ข้อมูลของตัวอย่างเป็นข้อมูลจริง (ชื่อ เลขบัตร ค่าจ้าง เลขบัญชีนายจ้าง) — **ทุกไฟล์ในขั้นตอนนี้อยู่นอก git**

1. สร้างโฟลเดอร์นอก repo แล้วใส่ `kor2.json` และ `register.json` (ข้อมูลของตัวอย่าง `แบบ คร2.pdf` / `ทะเบียนผู้ประกันตน.pdf`
   ในรูป `Kor2Employee` + `Kor2Input` + `EmployerOptions` และ `InsuredPersonLine[]` + `EmployerOptions` — ดูเทสต์
   `Prints_the_overlay_check_pdfs_when_asked` ใน `tests/Lockte.Web.Tests/GovernmentFormPdfTests.cs`)
2. พิมพ์ PDF ของระบบใหม่ลงโฟลเดอร์นั้น:
   ```bash
   LOCKTE_FORM_OVERLAY_DIR=<โฟลเดอร์> dotnet test tests/Lockte.Web.Tests --filter "FullyQualifiedName~Prints_the_overlay"
   ```
3. เทียบ (ต้องมี PyMuPDF):
   ```bash
   python -I tools/form-overlay/compare.py "<ตัวอย่างเดิม.pdf>" <โฟลเดอร์>/kor2.pdf <โฟลเดอร์> --pages 1
   ```
   ได้รายการข้อความทีละชิ้น ว่าจุดเริ่ม จุดจบ และเส้นฐานคลาดกี่ มม. (`!` = เกิน 2 มม.) และภาพ `overlay-<หน้า>.png`:
   แดง = เดิม, น้ำเงิน = ใหม่, ม่วง = ทับกัน — ใช้ให้ HR ดูประกอบการเซ็นรับ

ผล #64 (19–20 ต.ค. 2569): แบบ คร.2 134 ชิ้น คลาดสูงสุด 1.3 มม. · ทะเบียนผู้ประกันตน 2 หน้า 425 ชิ้น คลาดสูงสุด 1.4 มม.
ข้อความที่ "ไม่พบ" มีเฉพาะที่ตั้งใจเปลี่ยน: ค่าจ้าง `#####` → ตัวเลข (D-2), "เดิอน" → "เดือน", และหัวคอลัมน์สองช่องที่ PDF เดิมรวมเป็นชิ้นเดียว
