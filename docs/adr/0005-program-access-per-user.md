# สิทธิ์เข้าโปรแกรมต่อ user (แก้ "ไม่มีสิทธิ์รายหน้าจอ" ของ ADR 0004)

ADR 0004 บันทึกว่ายังไม่มีบทบาทและไม่มีสิทธิ์รายหน้าจอ — ผู้ใช้ระบบทุกคนเปิดได้ทั้ง 5 โปรแกรม ต่อมา (2026-11-24) ผู้ใช้ส่งใบ
"จำนวนคนใช้ program" รายชื่อผู้ใช้งานจริง 18 แถว (office 1–8, factory 9–18) พร้อมติ๊กว่าแต่ละคนใช้โปรแกรมใดบ้าง
(พนักงาน / ผลผลิต / วัตถุดิบ / เงินสดย่อย / สอบเทียบ) และขอให้ระบบกันคนที่ไม่ได้ติ๊กออกจากโปรแกรมนั้น ADR นี้เพิ่ม
**สิทธิ์ระดับโปรแกรม** เท่านั้น — ยังไม่มีบทบาท และยังไม่มีสิทธิ์รายหน้าจอภายในโปรแกรม

## การตัดสินใจ

- `AppUser.Programs` เก็บคีย์โปรแกรมที่เปิดได้ คั่นด้วยจุลภาค เรียงตามหน้าเลือกโปรแกรมเสมอ (`hr,order,purch,calib,cash`)
  ใน `auth.AspNetUsers` เข้าประวัติการแก้ไขในชื่อ "เข้าโปรแกรมได้" (ADR 0003) admin ติ๊กทีละโปรแกรมที่หน้าจัดการ user
- ตอน login ออกเป็น claim `lockte:program` หนึ่งตัวต่อโปรแกรม การเปลี่ยนสิทธิ์อัปเดต security stamp จึงมีผลเมื่อเข้าระบบใหม่
  (เหมือน "ดูข้อมูลค่าจ้างได้")
- **user ที่มีอยู่ก่อน ADR นี้ได้ครบ 5 โปรแกรม** (migration `UserPrograms`) — user ทดสอบ user1 / user2 ใช้ได้เหมือนเดิม;
  user ที่เพิ่มใหม่เริ่มที่ "ไม่มี" จนกว่า admin จะติ๊ก
- **admin ไม่เข้าโปรแกรมงานใดเลย** ไม่ว่าเก็บค่าอะไร (เหมือนเดิม: admin เห็นเฉพาะหน้าจัดการ user และประวัติ)
- สิทธิ์เข้าโปรแกรม **แยกจาก** "ดูข้อมูลค่าจ้างได้": ข้อมูลค่าจ้างต้องได้ทั้งโปรแกรมพนักงานและธงค่าจ้าง
- ผู้ใช้ชุดแรกตามใบ (user01–user18, ชื่อที่แสดงตามคอลัมน์ 3) สร้างด้วยคำสั่งบนเซิร์ฟเวอร์ `Lockte.Web seed-users`
  รหัสชั่วคราวเดียวกันทุกคน ต้องเปลี่ยนตอน login ครั้งแรก; ใช้เลข 2 หลักเพื่อไม่ชนกับ user1 / user2; แถว "สำรอง"
  (7, 8, 17, 18) สร้างไว้แต่ไม่มีโปรแกรม; ไม่มีใครได้ "ดูข้อมูลค่าจ้างได้" ตั้งแต่แรก; รันซ้ำได้ (user ที่มีอยู่ไม่ถูกแก้)

## จุดบังคับ

1. **หน้าเลือกโปรแกรม / ตัวสลับโปรแกรม** แสดงเฉพาะโปรแกรมที่ได้รับ
2. **หน้าจอ** — `MainLayout` หาโปรแกรมของหน้าจาก `ProgramMenus.Of(path)` (เมนู หน้าจอ และหน้าใต้เมนู เช่น `menu/n`,
   `org/departments` เป็นของโปรแกรมพนักงาน) ถ้าเป็น staff ที่ไม่ได้โปรแกรมนั้น แสดงข้อความแทนและไม่สร้างหน้า
   หน้าที่ไม่ใช่ของโปรแกรมใด (เลขเอกสารควบคุม, เปลี่ยนรหัสผ่าน) เปิดได้เหมือนเดิม
3. **รายงาน** — ทุกเส้นทางอยู่ใต้ `/reports/{คีย์โปรแกรม}/…` และได้ policy `program:{คีย์}` (`RequireProgramOfRoute`)
   ผู้ไม่มีสิทธิ์ได้ **403**; เทสต์ล้มถ้ามีรายงานใหม่ที่ไม่อยู่ใต้โปรแกรมใด

## Considered Options

- **บทบาท (office / factory / QA)**: ใบของผู้ใช้ติ๊กรายคน และคนในกลุ่มเดียวกันได้ไม่เท่ากัน (แต๋ว นก บอม) จึงเก็บรายคน
- **สิทธิ์รายหน้าจอ**: ผู้ใช้ไม่ได้ขอ และยุ่งเกินจำเป็นสำหรับผู้ใช้ราว 20 คน
- **ซ่อนที่หน้าเลือกโปรแกรมอย่างเดียว**: ไม่พอ เพราะพิมพ์ URL หรือเปิดรายงานตรงได้ จึงบังคับที่หน้าจอและรายงานด้วย

## Consequences

- เพิ่มรายงานใหม่ต้องอยู่ใต้ `/reports/{คีย์โปรแกรม}` (เทสต์ตรวจ) ส่วนหน้าจอใหม่ต้องอยู่ใต้ root ของโปรแกรมหรือบนเมนูของโปรแกรม
- ผู้ใช้ที่ถูกเปลี่ยนสิทธิ์ต้องเข้าระบบใหม่
- service ชั้นข้อมูลไม่ได้ตรวจสิทธิ์โปรแกรม (ต่างจากข้อมูลค่าจ้าง): กันที่หน้าจอและรายงาน ซึ่งเป็นทางเข้าเดียวของผู้ใช้
