# สิทธิ์ดูข้อมูลค่าจ้างเป็นธงต่อ user หนึ่งช่อง (แก้ข้อกำหนด "ไม่มีบทบาท" ของ #39)

ตั๋ว #39 ตัดสินว่าระยะแรก "ไม่มีบทบาทหรือสิทธิ์ตามบทบาท" (gate มีสี่แบบ: Staff / Admin / StaffOrAdmin / SignedIn) ต่อมาผู้ใช้ขอให้บาง user เห็นหรือไม่เห็นข้อมูลค่าจ้าง โดยแสดงเป็น `***` แทน (ข้อ 3 ของรายการปรับปรุง UAT, ตั๋ว #277) ผู้ใช้ตัดสินใจไว้ในตั๋วว่า **ธงต่อ user หนึ่งช่อง "ดูข้อมูลค่าจ้างได้" ตั้งโดย admin ที่หน้าจัดการ user** ไม่ทำเป็นบทบาท (HR / ผู้จัดการ / ทั่วไป) เพราะมีผู้ใช้ราว 10 คนและธงเดียวง่ายกว่า — ADR นี้บันทึกว่าข้อกำหนดเดิมเปลี่ยนเป็นอะไร และสิ่งที่ **ไม่** เปลี่ยน: ยังไม่มีบทบาท ไม่มีสิทธิ์รายหน้าจอ และ gate เดิมสี่แบบทำงานเหมือนเดิม

## การตัดสินใจ

- **ข้อมูลค่าจ้าง** = ค่าแรงรายวัน/เดือน, ค่าแรงที่คำนวณ, OT, โบนัส, เงินสงเคราะห์/สะสม, เลขบัญชีธนาคาร ของโปรแกรมพนักงานและค่าแรง (ค่าราคา/ต้นทุนฝั่ง ORDER ไม่รวม)
- ธง `AppUser.CanViewPay` เก็บใน `auth.AspNetUsers` ออกเป็น claim `lockte:view_pay` ในคุกกี้ตอน login และเป็น policy `ViewPay` (= Staff + มี claim) การเปลี่ยนธงอัปเดต security stamp จึงมีผลเมื่อเข้าระบบใหม่ และเข้าประวัติการแก้ไขตามปกติ (ADR 0003: "ดูข้อมูลค่าจ้างได้" ของตาราง "ผู้ใช้")
- **ผู้ใช้เดิมทุกคนเริ่มเป็น "ได้"** (migration ตั้งค่าเริ่มต้นของแถวที่มีอยู่เป็นจริง) งานไม่หยุด; user ที่เพิ่มใหม่หลังจากนี้เริ่มเป็น "ไม่ได้" จนกว่า admin จะติ๊ก
- **admin ไม่เห็นข้อมูลค่าจ้างเสมอ** ไม่ว่าธงเก็บค่าอะไร (`AccountClaims.CanViewPay` ตัด admin) และตั้งธงให้ admin ไม่ได้
- ผู้ไม่มีสิทธิ์ **ทำงานอื่นของหน้าเดียวกันได้** แก้ช่องที่ซ่อนไม่ได้ และค่าที่ซ่อนไม่เปลี่ยนเมื่อบันทึก

## จุดบังคับ (จุดเดียวต่อชั้น ไม่เช็กมือทีละหน้า)

1. **service (ชั้นข้อมูล)** — `IPayAccess` (SharedKernel) ฝั่ง web อ่านธงจาก user ที่กำลังทำงาน; `EmployeeDirectory` / `LeaveDirectory` ไม่ส่งค่าจ้างออกให้ผู้ไม่มีสิทธิ์ (ค่าเป็น 0/ว่าง) และ `EmployeeRegistry` / `LeaveRegistry` ไม่แก้ค่าจ้างตามที่หน้าจอส่งมา งานนอก user (เครื่องมือย้ายข้อมูล, reset-admin) เห็นทั้งหมด
2. **หน้าจอ** — `<PayView>` แสดง `***` (หรือข้อความแทนปุ่ม) ทุกที่ที่ปนอยู่ในหน้าที่ใช้งานอื่นได้; หน้าที่เป็นค่าจ้างล้วน (โบนัส ปรับค่าแรง ค่าพักร้อน เงินชดเชย ค่าแรงสองช่วง งานรับจ้าง รายงานค่าแรงสะสม แบบ คร.2) ใช้ `@layout PayGateLayout` ไม่สร้างหน้าให้ผู้ไม่มีสิทธิ์
3. **รายงาน / ไฟล์ส่งธนาคาร / สลิป** — `PayReportRoutes` เป็นรายการเดียวของเส้นทางที่มีค่าจ้าง ผูก policy `ViewPay` ผู้ไม่มีสิทธิ์ได้ **403** (ไม่ใช่รายงานที่พิมพ์เป็น `***`); เส้นทางใต้ `/reports/hr` ทุกเส้นต้องถูกจัดเป็น Pay / Mixed / NoPay ไม่เช่นนั้นเทสต์ล้ม

## Considered Options

- **บทบาท (HR / ผู้จัดการ / ทั่วไป)**: ยืดหยุ่นกว่าแต่เกินความจำเป็นสำหรับผู้ใช้ราว 10 คน และขัดกับการตัดสินใจของ #39 มากกว่า; เพิ่มภายหลังได้โดยให้ policy `ViewPay` คำนวณจากบทบาทแทนธง
- **พิมพ์รายงานให้ผู้ไม่มีสิทธิ์เป็น `***`**: ผู้ใช้เลือกไม่ทำ — รายงานที่มีค่าจ้างพิมพ์/ส่งออกไม่ได้เลย
- **ซ่อนที่หน้าจออย่างเดียว**: ไม่พอ เพราะค่ายังไหลเข้า circuit และบันทึกทับตอน save ได้; จึงบังคับที่ service ด้วย

## Consequences

- เพิ่มรายงานหรือหน้าใหม่ที่มีค่าจ้างต้องจัดเข้า `PayReportRoutes` หรือใช้ `PayView` / `PayGateLayout` — เทสต์ตรวจเส้นทางรายงาน แต่หน้าจอ (Razor) ตรวจในรีวิว
- ตัวเลือกเมนูที่ลิงก์ตรงไปรายงานค่าจ้างยังแสดงอยู่ ผู้ไม่มีสิทธิ์กดแล้วเจอ 403
- ผู้ใช้ที่ถูกเปลี่ยนธงต้องเข้าระบบใหม่ (security stamp เปลี่ยน) สิทธิ์จึงเปลี่ยน
