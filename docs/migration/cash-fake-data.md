# ฐานทดสอบ UAT และชุดสาธิตตัวเลขของโปรแกรมเงินสดย่อย (#247)

ผู้ถือเงินสดย่อยและผู้ขายของเก่าลองระบบบนฐานทดสอบแยกจากฐานจริง แล้วรีเซ็ตกลับเองได้ มีสองแบบ — เลือกตามที่ต้องการลอง

| แบบ | ข้อมูล | คำสั่ง | ใช้เมื่อ |
|---|---|---|---|
| **ชุดสาธิตตัวเลข** | ข้อมูลปลอมชุดเล็ก (ประมาณ 18 บรรทัดค่าใช้จ่าย, 5 ใบเสร็จ) ตั้งยอดให้ตรง `acceptance.md` | `tools/uat/Reset-CashFake.ps1` | ฝึกใช้ ตรวจว่าโปรแกรมให้ตัวเลขตามเอกสาร ลองบนเซิร์ฟเวอร์ที่ใครก็เข้าถึงได้ |
| **ข้อมูลจริงที่ย้าย** | สำเนา `เงินสดย่อย.accdb` ย้ายด้วย `--program cash` | `tools/uat/Reset-Uat.ps1 … -Cash <ไฟล์> -AllowRealCash` | ลองกับข้อมูลรูปร่างจริง เทียบกับ Access (ข้อตัดสินผู้ใช้ 29 ต.ค. 2569: ใช้ข้อมูลจริงได้ — **ข้อมูลจริงอยู่ในฐานข้อมูลเท่านั้น ห้ามเข้า git/เอกสาร**) |

ทั้งสองลบฐานแล้วสร้างใหม่ จึงรีเซ็ตกลับได้ในไม่กี่นาทีด้วยคำสั่งเดิม · ปฏิเสธถ้าชื่อฐานไม่ใช่ฐานทดสอบ (ต้องขึ้นต้น `Lockte` ลงท้าย `Uat`/`Test`/`Dev` และไม่ใช่ `Lockte`) หรือฐานตั้งธงเปิดใช้งานจริงแล้ว (`Lockte.GoLive`) · ใช้ชื่อฐานแยกจาก `LockteUat` (ข้อมูลพนักงาน/ORDER) เพราะสคริปต์ลบฐานก่อน

## ชุดสาธิตตัวเลข

```powershell
$env:LOCKTE_UAT_SQL = 'Server=...;User Id=...;Password=...;TrustServerCertificate=True'   # ไม่ใส่ Database
.\tools\uat\Reset-CashFake.ps1 -Database LockteCashUat -AdminPassword 'ตั้งรหัสชั่วคราวเอง'
```

สร้างโครงฐาน (เว็บแอป migrate + ตั้งรหัส admin) แล้วเติมข้อมูลปลอมด้วย `Lockte.Web seed-cash-fake` · เติมเข้าฐานที่สร้างโครงไว้แล้วโดยไม่ลบ: `dotnet run --project src\Lockte.Web -- seed-cash-fake` (ฐานที่มีชุดนี้แล้วถูกปฏิเสธ)

### ตัวเลขที่ควรเห็น

ชื่อทุกชื่อในชุดเป็นชื่อสมมติ ("คุณตัวอย่าง …", ทะเบียนรถ "กข 0001", เบอร์ `000-…`)

| ตรวจ | ทำอย่างไร | ได้ |
|---|---|---|
| AC-06 ใบสำคัญจ่าย | บันทึก/แก้ไข ลบค่าใช้จ่าย → วันที่ 9/9/2569 → ติ๊กสามบรรทัดของเลขที่ `09/30` → พิมพ์ใบสำคัญจ่าย | รวมเงิน 140.00 "(หนึ่งร้อยสี่สิบบาทถ้วน)" |
| AC-07 สรุปค่าใช้จ่าย | พิมพ์สรุปค่าใช้จ่ายเงินสดย่อย 1/9/2569–3/9/2569 ค่าใช้จ่ายงวดที่แล้ว 21,456 | 9 ประเภท รวมงวดนี้ 28,710.00 รวมทั้งสิ้น 50,166.00 "(ห้าหมื่นหนึ่งร้อยหกสิบหกบาทถ้วน)" |
| AC-20 รายการซื้อของ | พิมพ์รายงานการซื้อของ 11/9/2569–11/9/2569 | 3 บรรทัด (09/34 633.00, 09/35 90.00, 09/36 80.00) รวม 803.00 |
| AC-10 ใบเสร็จ | แก้ไข/พิมพ์ซ้ำ ใบเสร็จเลขที่ 69029 | 5 บรรทัด รวม 2,270.00 "(สองพันสองร้อยเจ็ดสิบบาทถ้วน)" |
| AC-15 / BR-018 ยอดขายของเก่า | รายงานยอดขายของเก่า 1/9/2569–30/9/2569 และ 5/8/2569 | 6 บรรทัด 3,270.00 (ใบ 69028 + 69029) · 4 บรรทัด 1,360.00 (ใบ 69027) |
| AC-13 ตัดยอดนำส่ง | ยอดรอนำส่ง = 69027, 69028, 69029 (รวม 4,630.00) → ตัดยอดเลขที่ 69028–69029 | ใบสรุป 2 ใบ 3,270.00 และเหลือ 69027 รอนำส่ง (69025–69026 นำส่งไปแล้ว) |

ลองบันทึกค่าใช้จ่ายใหม่ ออก/แก้/ยกเลิกใบเสร็จ (ยกเลิกใบที่นำส่งแล้วไม่ได้) ตัดยอด แล้วรีเซ็ตกลับด้วยคำสั่งเดิม · เทสต์ที่ commit (`CashFakeDataTests`) ตรวจตัวเลขข้างบนผ่าน service/รายงาน และตรวจว่าเติมซ้ำถูกปฏิเสธและสองฐานได้ชุดเดียวกัน

## ข้อมูลจริงที่ย้ายมา

```powershell
.\tools\uat\Reset-Uat.ps1 -Database LockteCashRealUat -AdminPassword '…' -Employee <พนักงาน-fake.accdb> -Order <ผลผลิตและORDER_fake.accdb> `
    -Cash <สำเนา เงินสดย่อย.accdb> -AllowRealCash [-CashMap <cash-code-map.csv>] -Out <โฟลเดอร์รายงานนอก git>
```

หรือรันเฉพาะเงินสดย่อยลงฐานที่สร้างโครงไว้แล้ว (ดู [`full-run.md`](full-run.md) หัวข้อเงินสดย่อย) · ไฟล์ Access สำเนา, ไฟล์จับคู่ที่มีชื่อจริง, รายงาน DQ รายแถว เก็บนอก repo เสมอ

**ตรวจกับ Access (ก.ย. 2569):** ตัวอย่างเดียวกับตารางข้างบนต้องให้ตัวเลขเดียวกันบนข้อมูลที่ย้ายมา — ซ้อมแล้วบนสำเนา 2026-09-12 (ฐานทดสอบชื่อแยก): สรุปค่าใช้จ่าย 1–3 ก.ย. = 9 ประเภท 28,710.00 / 50,166.00, รายการซื้อของ 11 ก.ย. = 3 บรรทัด 803.00, ใบ 69029 = 5 บรรทัด 2,270.00, ยอดขายของเก่า ก.ย. = 6 บรรทัด 3,270.00, 5 ส.ค. = 4 บรรทัด 1,360.00 (ใบสำคัญจ่าย 09/30 วันที่ 9 ก.ย. มี 4 บรรทัดในข้อมูลจริง ตัวอย่าง AC-06 เลือก 3 บรรทัดรวม 140.00)

## ปัญหาที่พบบ่อย

- PowerShell ไม่ยอมรันสคริปต์: ปลดล็อกเฉพาะหน้าต่างด้วย `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force` (ดู `full-run.md`) · สคริปต์ `.ps1` เก็บเป็น UTF-8 มี BOM
- "ชุดข้อมูลปลอมถูกเติมในฐานนี้แล้ว": ใช้ `Reset-CashFake.ps1` ซึ่งลบฐานก่อน ไม่ใช่ `seed-cash-fake` ซ้ำ
