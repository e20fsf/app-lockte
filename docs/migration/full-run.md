# คู่มือย้ายข้อมูลทั้งชุด (พนักงาน + ผลผลิตและORDER)

> ไม่มีข้อมูลจริงในเอกสารนี้ · เครื่องมือ: `src/Lockte.Migration` (รันบน Windows ที่มี Microsoft Access Runtime / ACE OLE DB 16.0 — ไม่รันบนเซิร์ฟเวอร์ ADR 0001) · ตั๋ว #134

## ภาพรวม

คำสั่งเดียวรันตามลำดับพึ่งพา: **พนักงาน.accdb** (ข้อมูลหลัก ประวัติ ค่าแรง) → **ผลผลิตและORDER.accdb** (ข้อมูลหลัก ORDER/ประวัติ/การส่ง ใบรายงานผลผลิต สต็อก แม่พิมพ์) → (ถ้าระบุ) **สเปคตรวจ QA**
ลูกค้าและเขตการขายใช้ร่วมกันทั้งสองโปรแกรม (โหลดแบบ upsert) · ทุกขั้นลบแล้วโหลดใหม่เฉพาะส่วนของตน จึง **รันซ้ำได้** ผลเท่าเดิม ไม่เพิ่มแถว · ได้รายงานฉบับเดียว

## 1. เตรียมสำเนา

1. ปิดโปรแกรม Access ที่เปิดไฟล์อยู่ ทำสำเนา `พนักงาน.accdb` และ `ผลผลิตและORDER.accdb` ไปไว้นอกโฟลเดอร์ใช้งาน (เครื่องมืออ่านจากสำเนาอีกชั้นหนึ่ง ไม่แก้ไฟล์ต้นทาง)
2. จดวันเวลาที่ทำสำเนา (รายงานบันทึกวันที่แก้ไขล่าสุดของไฟล์และเวลาที่อ่านให้ด้วย)
3. ฐานข้อมูล SQL Server ต้องสร้างโครงแล้ว (เปิดเว็บแอปกับฐานนั้นหนึ่งครั้ง — หรือใช้ `tools/uat/Reset-Uat.ps1` สำหรับฐานทดสอบ)

## 2. รัน

```
dotnet run --project src/Lockte.Migration -c Release -- --program all ^
    --employee "<พนักงาน.accdb>" --order "<ผลผลิตและORDER.accdb>" [--qa "<reports_decompiled>"] ^
    --connection "<connection string>" --confirm <ชื่อฐาน> --out "<โฟลเดอร์รายงาน>" [--map code-map.csv] [--remove-stock-duplicates yes]
```

- `--connection` ใช้ env `LOCKTE_MIGRATION_SQL` แทนได้ (ไม่ต้องพิมพ์รหัสผ่านในคำสั่ง) · `--confirm` ต้องพิมพ์ชื่อฐานซ้ำ เพราะทุกรอบลบข้อมูลก่อนโหลด
- ไฟล์ที่ไม่ใช่ Access, เล็กเกินไป, เปิดอ่านไม่ได้ หรือไม่พบ → หยุดก่อนลบอะไร พร้อมข้อความบอกเหตุ · ขั้นใดล้มเหลวกลางทาง → ข้อความบอกว่าฐานอาจโหลดไม่ครบ ให้แก้เหตุแล้วรันซ้ำทั้งชุด
- เวลา: ไฟล์ผลผลิตและORDER ประมาณ 600 MB การอ่านและโหลดใช้เวลาหลายนาทีถึงสิบกว่านาที (ดูตัวเลขจริงของรอบล่าสุดใน `run-info.csv`)
- `--remove-stock-duplicates yes` = ตัดผลผลิตเดือน ธ.ค. 2568 ที่นับซ้ำใน P_ST (Q-47) — ใช้ตอนซ้อมก่อนปิดปี; ค่าเริ่มต้นไม่ตัด รายงานจำนวนอย่างเดียว
- `--qa` คือโฟลเดอร์ `reports_decompiled` ที่กู้ไว้ (สเปคตรวจเป็นข้อมูลเทคนิคของบริษัท **ห้ามโหลดขึ้นฐานที่ลูกค้าเข้าถึงได้**)

## 3. อ่านรายงาน (`<โฟลเดอร์รายงาน>`)

| ไฟล์ | ความหมาย |
|---|---|
| `summary.md` | อ่านก่อน: เวลาแต่ละขั้น, ตรง/ไม่ตรง, จำนวนแถว (AC-20), ข้อยกเว้น DQ จัดกลุ่ม (ปัญหา จำนวน การจัดการ), หมายเหตุของแต่ละขั้น |
| `dq-summary.csv` | ข้อยกเว้นจัดกลุ่มตามขั้น/ตาราง/ลักษณะปัญหา/การจัดการ + จำนวน |
| `dq-exceptions-all.csv` | ข้อยกเว้นรายแถวทั้งหมด (**มีข้อมูลจริง เก็บนอก git**) |
| `row-counts-all.csv` | ต่อตาราง: แถวต้นทาง = ไม่ย้ายตามกติกา + ข้อยกเว้น DQ + โหลด และโหลด = ในฐานข้อมูล |
| `monthly-totals-all.csv` | ยอดรวมต่อเดือน/ต่อวันตัด: ต้นทาง / ที่ควรโหลด / ที่อยู่ในฐานข้อมูล |
| `run-info.csv` | ไฟล์ต้นทาง ขนาด วันที่แก้ไข เวลาที่อ่านสำเนา ใช้เวลา |
| `01-employee/`, `02-order/`, `03-qa-spec/` | รายงานเดิมของแต่ละขั้น (รวม code-map-used.csv) |

หลัก "ออกแบบใหม่ให้ถูกต้อง": แถวเก่าที่ขัดกับโครงที่ถูกต้อง (คีย์ซ้ำ รหัสที่ไม่มีในทะเบียน) ลง DQ และ **ไม่ถูกโหลด** — ไม่มีการสร้างระเบียนหลอกให้แถวเก่าโหลดได้; ตัวเลขเทียบกับ Access (AC-16/17/19) ใช้กับส่วนที่โหลดได้ถูกต้อง โดยระบุรายการที่ไม่รวมจาก DQ

### ตารางจับคู่รหัส

ไฟล์ CSV เดียว (`--map`) ใช้กับทุกขั้น: `kind,legacy,code,name,prefix` · ชนิดที่รองรับ: แผนก, ลูกค้า, กะ, พนักงานผลิต, พนักงานขาย · ดูรหัสที่ใช้จริงและที่ยังไม่ได้ตัดสินใน `code-map-used.csv` (คอลัมน์ source) เติมคำตัดสินในไฟล์ของคุณแล้วรันซ้ำ · ใน repo เก็บเฉพาะรหัสและคำตัดสิน ไม่มีชื่อบุคคล

## 4. รันซ้ำ

รันคำสั่งเดิมอีกครั้ง — ตรวจ `row-counts-all.csv` ว่าจำนวนเท่ารอบก่อน (เทสต์ `FullMigrationTests` ตรวจเรื่องนี้กับไฟล์ปลอม) ถ้าไฟล์ต้นทางเปลี่ยน ให้ทำสำเนาใหม่

## 5. ฐานทดสอบ UAT (ข้อมูลปลอมเท่านั้น)

ฐานที่ลูกค้าเข้าถึงได้ใช้ **ข้อมูลปลอมเท่านั้น**

1. สร้างไฟล์ปลอม (ครั้งเดียว หรือเมื่อสำเนากลางเปลี่ยน) — `tools/order-fake-data/make_fake.py <ต้นทาง.accdb> <ปลอม-fake.accdb>` (ผลผลิตและORDER) และ `source/samples/พนักงาน/tools/make_fake.py` (พนักงาน): ปิดชื่อลูกค้า/เซล/พนักงาน ที่อยู่ เบอร์โทร คูณยอดเงินต่อแถวด้วยตัวคูณ 0.85–1.15 ต่อลูกค้า/สินค้า ตัดข้อมูลก่อนปี 2568 ตรวจรั่วไหลต้องได้ 0 ค่า ไฟล์ผลลัพธ์อยู่ใน `source/samples/` (ไม่เข้า git)
2. ตั้งหรือรีเซ็ตฐาน: ตั้ง env `LOCKTE_UAT_SQL` (connection string ไม่ใส่ Database) แล้ว

```
.\tools\uat\Reset-Uat.ps1 -Database LockteUat -Employee <พนักงาน-fake.accdb> -Order <ผลผลิตและORDER_fake.accdb> -AdminPassword <รหัสชั่วคราว> -Out <โฟลเดอร์รายงาน> -RemoveStockDuplicates
```

สคริปต์ปฏิเสธถ้า: ชื่อฐานไม่ใช่ฐานทดสอบ (ต้องลงท้าย Uat/Test/Dev และไม่ใช่ `Lockte`), ไฟล์ไม่มีคำว่า fake, หรือฐานตั้งธงเปิดใช้งานจริงแล้ว · ผู้ใช้ลองกดโอนผลผลิต เบิก พิมพ์ SALE ORDER ฯลฯ แล้วรีเซ็ตกลับด้วยคำสั่งเดิม (ลบฐาน สร้างใหม่ ย้ายข้อมูลใหม่)

## 6. วัน D และหลังจากนั้น

- รอบสุดท้ายก่อนวัน D: รันบนไฟล์ที่ปิดปีแล้ว (ขั้นปิดปีดูที่ตั๋ว #135) + รายการตั้งแต่ 1 ม.ค. 2570 ที่คีย์ใน Access
- หลังเปิดใช้งานจริง ตั้งธงบนฐานจริงด้วย `--program mark-go-live --connection ... --confirm <ชื่อฐาน>` (เขียน extended property `Lockte.GoLive` ลงฐาน) — จากนั้นเครื่องมือ **ไม่ยอมรัน** บนฐานนี้ (รันซ้ำจะลบงานของผู้ใช้) ถ้าต้องรันซ้ำจริง ๆ ต้องลบ property นั้นเองด้วย `EXEC sp_dropextendedproperty N'Lockte.GoLive'`
