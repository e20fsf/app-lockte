# ย้ายข้อมูลหลักของเงินสดย่อย (#231)

ย้าย 3 ทะเบียนของ `เงินสดย่อย.accdb` เข้า schema `cash`: ประเภทค่าใช้จ่าย ผู้ซื้อของเก่า ชนิดของเก่า — ฐานทดสอบแยกชื่อเท่านั้น (ไม่ใช่ `Lockte`/`LockteUat`/`LockteTheme`) · อ่านจากสำเนาไฟล์ ไม่แตะต้นฉบับ

```powershell
dotnet run --project src\Lockte.Migration -- --program cash --source "<สำเนา เงินสดย่อย.accdb>" `
  --connection "<SQL Server connection string>" --confirm <ชื่อฐาน> --out <โฟลเดอร์นอก git> [--map <cash-code-map.csv>]
```

เปิดเว็บแอปกับฐานนั้นหนึ่งครั้งก่อน (สร้าง schema) · ลบข้อมูลหลักของ `cash` แล้วโหลดใหม่ รันซ้ำได้ผลเท่าเดิม

## ผลลัพธ์ (ใน `--out` — มีข้อมูลจริง ห้าม commit)

| ไฟล์ | อะไร |
|---|---|
| `row-counts.csv` | ตรวจยอด: ต้นทาง = ไม่ย้าย + DQ + โหลด และโหลด = ในฐานข้อมูล · 4 แถว: ค่าใช้จ่ายต่างๆ (ใช้งาน), ซื้อของเงินสด.TYPE (เลิกใช้), ผู้ซื้อของเก่า, รายชื่อของเก่า |
| `dq-exceptions.csv` | รายแถว: ชื่อซ้ำหลังตัดช่องว่าง, ขึ้นบรรทัดใหม่ (Q-27), ประเภทที่ใช้ในข้อมูลแต่ไม่อยู่ในทะเบียน (Q-05), ประเภท/ผู้ซื้อ/ชนิดที่ไม่ถูกใช้เลย |
| `code-map-used.csv` | ทุกชื่อใน `ซื้อของเงินสด.TYPE` และประเภทที่ได้ — แก้แล้วส่งกลับเป็น `--map` ของรอบถัดไป |
| `source-info.csv` | หมายเหตุ: DQ จัดกลุ่ม (ปัญหา, จำนวน, การจัดการ) และตารางที่ไม่ย้ายพร้อมเหตุผล |

## รวมชื่อที่สะกดต่าง (ข้อสมมติ ซ)

ชื่อใน `TYPE` ที่ไม่อยู่ในทะเบียนถูกสร้างเป็นประเภท "เลิกใช้" ตามข้อความเดิม (หลังตัดช่องว่างและขึ้นบรรทัดใหม่) เพื่อให้สรุปตามประเภทตรง Access · ถ้าสองชื่อเป็นประเภทเดียวกัน (เช่นช่องว่างในทะเบียนรถ) ให้เติมแถวในไฟล์จับคู่ — `legacy` = ชื่อจาก `code-map-used.csv`, `code` = ชื่อประเภทที่ถูกต้อง — แล้วรันซ้ำ:

```csv
kind,legacy,code,name,prefix
cash-expense-type,<ชื่อที่สะกดต่าง>,<ชื่อประเภทที่ถูกต้อง>,,
```

ไฟล์จับคู่ที่เติมแล้วมีชื่อจริง — เก็บนอก git
