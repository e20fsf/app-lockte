# ด่านเทียบเงินสดย่อยกับ Access และเปิดใช้งาน (ตั๋ว #248, AC-01 · AC-16 · AC-23 · AC-24)

> ไม่มีข้อมูลจริงในเอกสารนี้ (ตัวเลขรวมจากการซ้อม) · เทียบ "ข้อมูลที่ย้ายมา" กับผลที่ Access ให้ทีละแถว · รายการรายแถวมีชื่อจริง เก็บนอก git · แบบอย่าง: [`compare-gate.md`](compare-gate.md) ของ ORDER

## วิธีทำ (รันซ้ำได้)

1. **สำเนา** — ทำสำเนา `เงินสดย่อย.accdb` (ปิด Access ที่เปิดไฟล์อยู่) ไว้นอก git เช่น `source/work/` · จดวันเวลาที่ทำ
2. **ย้ายข้อมูลลงฐานทดสอบชื่อเฉพาะ** — [full-run.md](full-run.md) หัวข้อเงินสดย่อย / [cash-fake-data.md](cash-fake-data.md) (`Reset-Uat.ps1 … -Cash <สำเนา> -AllowRealCash`) · ห้ามใช้ชื่อ `Lockte`/`LockteUat`/`LockteTheme` สำหรับการซ้อม
3. **ส่งออก baseline จาก Access** — `python -I -X utf8 tools/baseline/export_cash_baseline.py <สำเนา.accdb> <โฟลเดอร์ baseline> [--range รหัส,YYYY-MM-DD,YYYY-MM-DD]` · ต้องมี `pyodbc` และ ACE ODBC driver · สคริปต์ทำสำเนาชั่วคราวเองแล้วเปิดแบบอ่านอย่างเดียวผ่าน SQL ตามเงื่อนไขของ query รายงานเดิม: RPT-02 (รวม AMOUNT ตาม TYPE ดิบ), RPT-04 (เรียง DATE, SUF), RPT-08 (`ขายของเก่า1` รวมตาม NO), RPT-09 (เรียง DATE, NO, SUF), ยอดรวมใบเสร็จ (ผลรวม Single เป็น Double แล้วปัด 2 ตำแหน่งแบบ banker's = `CutDecimal`) · ช่วง: ทุกปีที่มีข้อมูล ทุกเดือนของ 24 เดือนล่าสุด ตัวอย่างของ `acceptance.md` (AC07 AC15 AC20 BR018-2) · ใช้เวลา ~10 วินาที ผลอยู่ใต้ `source/baseline/cash/` (ข้อมูลจริง ห้าม commit)
4. **เทียบ** —

```
dotnet run --project src/Lockte.Migration -c Release -- --program compare-cash --baseline <โฟลเดอร์ baseline> ^
    --connection "<SQL>" --out <โฟลเดอร์รายงาน> [--map <ไฟล์จับคู่ที่ใช้ตอนย้าย>]
```

   อ่านอย่างเดียว ไม่แก้ฐาน · ได้ `cash-summary.md` (ตาราง AC), `cash-gate.csv`, `cash-compare.csv` (ต่อรายงานต่อช่วง), `cash-compare-details.csv` (**รายการรายแถวที่ต่าง — ชื่อจริง นอก git**; คอลัมน์ "ที่มาของความต่าง" = `ข้อมูล` (ยอมรับพร้อมเหตุผล) หรือ `โปรแกรม` (ไม่ยอมรับ = ต้องแก้)) · exit code 0 = ผ่านทุกข้อที่ตรวจอัตโนมัติ
5. **ผู้ตัดสิน** — เจ้าของโครงการ + ผู้ถือเงินสดย่อย/ผู้ขายของเก่า อ่าน `cash-summary.md` และรายการ "ยอมรับ" ใน details · ใบสำคัญจ่ายและใบเสร็จ (ระดับ A) ตรวจด้วยตาตามระดับเอกสาร: วางซ้อนตัวอย่างด้วย `tools/form-overlay` + ผู้ใช้เซ็นรับ (ผู้ใช้เซ็นรับเอกสารระดับ A แล้ว 2 พ.ย. 2569)
6. **รอบสุดท้ายคืนก่อนเปิดใช้** — ทำสำเนาใหม่ของ Access ที่มีใบเสร็จ/ค่าใช้จ่ายที่คีย์หลังสำเนาล่าสุด → ย้ายใหม่ลงฐานจริงด้วย `--program cash` (ลบข้อมูล `cash` แล้วโหลดใหม่ — ทำก่อนมีใครคีย์ในระบบใหม่) → เทียบอีกครั้ง → ตั้ง Access เป็นอ่านอย่างเดียว (ไม่รันคู่ขนาน — #29)
7. **ตั้งธงเปิดใช้งานจริง** — `--program mark-go-live --confirm <ฐาน>` หลังนั้น **ห้ามรันย้ายซ้ำบนฐานจริง**: `--program cash` และ `--program all` ปฏิเสธพร้อมข้อความ ("ฐานข้อมูลนี้ตั้งธง Lockte.GoLive แล้ว …") เพราะการย้ายลบแล้วโหลดใหม่ จะลบงานที่ผู้ใช้คีย์ · ถ้าต้องรันซ้ำจริง ๆ ให้ลบ extended property เอง (ข้อความบอกคำสั่ง)

## เกณฑ์ผ่าน

ส่วนที่ย้ายได้ **ต้องตรง 100%** (ไม่มีแถวที่หาย เกิน หรือยอดต่างโดยไม่มีเหตุผล) · ที่ต่างและยอมรับ แสดงพร้อมเหตุผลและจำนวน ไม่ปรับให้ตรง · ผลที่ไม่ตรงแยกว่า **ข้อมูลผิด** (ยอมรับได้ มีเหตุผล) หรือ **โปรแกรมผิด** (ต้องแก้) ในรายการเดียว

| เหตุผลที่ยอมรับ | ที่มา |
|---|---|
| บรรทัดไม่มีวันที่/เลขที่/รายการ/ประเภท (ค่าใช้จ่าย) หรือไม่มีเลขที่/รายการ/จำนวน (ใบเสร็จ) ไม่ย้าย | ระบบเดิมลบแถวเหล่านี้ตอนออกจากหน้าจอ (BR-003, BR-014) — ลงรายงาน DQ ของการย้าย |
| ชื่อประเภทดิบหลายชื่อรวมเป็นประเภทเดียว | ตัดช่องว่าง/ขึ้นบรรทัดใหม่ และไฟล์จับคู่ `cash-expense-type` (แสดงสองมุม: ต้นทางกี่ชื่อดิบ → ฐานกี่ประเภท; ยอดเทียบหลังรวม) |
| ชื่อรายการมีช่องว่างซ้อน ตัดเหลือช่องว่างเดียว | ย้ายข้อมูลทำเหมือนหน้าจอ |
| ใบเสร็จที่หัวต่างกันระหว่างบรรทัด ใช้วันที่ของบรรทัดแรก | DQ-Q16 — บรรทัดอื่นของใบนั้นจึงอยู่คนละวันที่กับที่รายงานเดิมให้ |
| ยอดรวมใบเสร็จที่ผลรวมเกิน 2 ตำแหน่งต่างจาก Access | AC-24 — ระบบใหม่ปัดจำนวนเงินทีละบรรทัด (2 ตำแหน่ง ครึ่งขึ้น) ก่อนรวม แล้วปัดผลรวมแบบ banker's; Access ปัดผลรวมของค่าเดิม — แจกแจงรายใบ ไม่ปรับให้ตรง |

หมายเหตุการเทียบ: ยอดต่อประเภทเทียบกับ Access ที่ **ประเภทหลังรวมชื่อ** (ระบบใหม่เก็บประเภทเป็น ID เดียว ไม่ใช่ข้อความ TYPE ดิบเหมือนเดิม) · ลำดับรายการ (RPT-04) เทียบกับลำดับ "วันที่ แล้วเลขที่แบบข้อความ" ที่ Access ให้ · ตัวเลขระบบใหม่เก็บจำนวน 3 ตำแหน่ง ราคา 4 ตำแหน่ง จำนวนเงิน 2 ตำแหน่ง (ค่าที่เกินลง DQ ตอนย้าย)
