# ด่านเทียบข้อมูลที่ย้ายกับ Access + ตาราง AC-01..23 (ตั๋ว #140)

> ไม่มีข้อมูลจริงในเอกสารนี้ (ตัวเลขรวมจากการซ้อม) · เทียบ "ข้อมูลที่ย้ายมา" กับ baseline ที่ส่งออกจากสำเนา Access **หลังปิดปี** ทีละแถว · ผลเทียบจริงมีรหัสจริง เก็บนอก git

## วิธีทำ (รันซ้ำได้)

1. **สำเนาหลังปิดปี** — ทำสำเนา `ผลผลิตและORDER.accdb` หลังขั้นปิดปี ([year-close-2569.md](year-close-2569.md)) ตั้งชื่อให้มีคำว่า `copy` (เช่น `rehearsal-copy.accdb`) ไว้นอก git (`source/work/...`) · ซ้อมก่อนปิดปีจริงได้ด้วย `tools/access-year-close/rehearse.py` บนสำเนา (ตัดสต็อก/แม่พิมพ์ ณ วันล่าสุดที่มีข้อมูล)
2. **ส่งออก baseline** — `python -I -X utf8 tools/baseline/export_baseline.py <สำเนา.accdb> <โฟลเดอร์ baseline> --cut YYYY-MM-DD` (วันตัดสต็อก/แม่พิมพ์ของสำเนานั้น) · อ่านสำเนาแบบอ่านอย่างเดียวผ่าน DAO ใช้ SQL ตามเงื่อนไขของรายงานเดิม: ODD join P_NAME (RPT-02), ORDER ประวัติ (RPT-06), ODDส่งออก join P_NAME (RPT-07), ต้นงวดP_ST วันตัด (RPT-13), P_ST (AC-09), ตันงวดการใช้งานของพิมพ์0 วันตัด (RPT-15), ใบผลผลิต 7 แผนก + สำเนา P_REP ที่โอนแล้ว (RPT-16) · ใช้เวลาไม่ถึงนาที
3. **ย้ายข้อมูลลงฐานทดสอบ** — [full-run.md](full-run.md) (ข้อมูลจริงลงได้เฉพาะฐานชั่วคราวชื่อเฉพาะบน dev SQL ที่ไม่มีเว็บชี้ แล้วลบทิ้งทันทีหลังเทียบ; ห้ามแตะ LockteUat/Lockte/LockteTheme)
4. **เทียบ** — `Lockte.Migration --program compare --baseline <โฟลเดอร์ baseline> --cut YYYY-MM-DD --connection "<SQL>" --out <โฟลเดอร์รายงาน>` (อ่านอย่างเดียว ไม่แก้ฐาน) → `compare-summary.md` (ตัวเลขรวม อ่านง่าย) และ `compare-details.csv` (รายการรายแถวที่ไม่ตรง/หักออก มีรหัสจริง เก็บนอก git) · exit code 0 = ผ่านครบ · ถ้าไม่ผ่านให้แก้ (ตัวเทียบหรือโค้ดโหลด) แล้วรันใหม่ — ส่งออก baseline ซ้ำและเทียบซ้ำได้โดยไม่ต้องย้ายข้อมูลใหม่ถ้าไม่ได้แก้โค้ดโหลด

## เกณฑ์ผ่าน และสิ่งที่ "หักออก"

ส่วนที่โหลดถูกต้อง **ต้องตรง 100%** (ไม่มีค่าไม่ตรง ไม่มีแถวที่มีเฉพาะฐานข้อมูล ไม่มีแถวต้นทางที่หายโดยไม่มีเหตุผล) · แถวของ baseline ที่ไม่ได้โหลดตามหลัก "ออกแบบใหม่" ถูกหักออก **พร้อมเหตุผล จำนวนแถวและยอดรวม** ในรายงาน ไม่ซ่อน:

| เหตุผลที่หักออก | ที่มา |
|---|---|
| วันที่ก่อน 1 ม.ค. 2568 | ย้ายประวัติ ORDER / การส่ง / ผลผลิต ตั้งแต่ 1 ม.ค. 2568 (ขอบเขตที่ตัดสินไว้); ระบบเดิมยังเก็บไว้ — เป็นก้อนใหญ่ที่สุดเพราะ baseline มีประวัติทุกปี |
| คีย์ซ้ำในต้นทาง — ใช้แถวแรก | ORDER เลขที่+ลำดับ+ลูกค้าเดียวกันซ้ำ (ข้อตัดสิน DQ-2) |
| ลูกค้า / รหัสสินค้า / แม่พิมพ์ไม่มีในทะเบียน | ไม่สร้างระเบียนหลอก — ลง DQ ไม่โหลด (หลักข้อมูลผิดในระบบเดิม) |
| ไม่มีลำดับบรรทัด (SUF_NO) / ไม่มีจำนวน | แถวที่โหลดไม่ได้ตามโครงที่ถูกต้อง (DQ) |
| รายการยกเลิก (MARK de) | ระบบเดิมทำเครื่องหมายไว้ลบ ไม่ย้าย (แสดงยอดแยก) |
| ใบรายงานที่ยังไม่โอนเข้าสต็อก | ระบบเดิมคำนวณ RPT-16 จากสำเนาที่โอนแล้ว (BR-020) ใบที่ยังไม่โอนไม่อยู่ในรายงานเดิมด้วย |
| ใบรายงานไม่มีวันที่ที่ใช้ได้ | ปี 1900 หรือไม่น่าเป็นไปได้ (DQ) |

หมายเหตุการเทียบที่ต้องรู้:
- **เลขที่ ORDER ที่ 2 ลูกค้าใช้ร่วมกัน** ระบบใหม่เปลี่ยนเป็น `nn-nn-nnnn-2` (เก็บเลขเดิม) → เทียบด้วยเลขเดิม + ลำดับ + รหัสลูกค้า
- **ผลผลิตต่อเดือน (RPT-16):** ระบบใหม่เก็บวันที่เดียวต่อใบ (วันที่น้อยที่สุดของใบ) ส่วนระบบเดิมนับตามวันที่ของแต่ละบรรทัด — ใบที่บรรทัดข้ามเดือนจึงนับเดือนต่างกัน (รวมทั้งปีไม่เปลี่ยน); ตัวเทียบนับ baseline ตามวันที่ของใบ และแสดงจำนวนบรรทัดที่ย้ายเดือนเป็นหมายเหตุ · **รอผู้ใช้ตัดสินว่ารับได้หรือต้องเก็บวันที่รายบรรทัด** (ดูรายการตัดสินใน PR)
- **มูลค่า RPT-13** = จำนวน × FML: ระบบใหม่เก็บราคาต่อหน่วยทศนิยม 4 ตำแหน่ง ผลต่างต่อแถวไม่เกิน 0.00005 × จำนวน (นับว่าตรง) รวมทั้งรายงานต่างไม่ถึง 0.02 บาท
- รหัสเทียบแบบไม่สนตัวพิมพ์ (Access ไม่แยก ระบบใหม่เก็บตามทะเบียน)
