## วิธีตรวจและขอบเขต

1. **ทุกหน้าใน `EmployeeMenu.cs` / `OrderMenu.cs`** (113 เส้นทาง + หน้าเมนูย่อยทั้งหมด): โหลดหน้า รอ Blazor วาดเสร็จ แล้วดู
   (ก) ถูก redirect/404 ไหม (ข) แถบ `blazor-error-ui` ขึ้นไหม (ค) JS error (ง) ข้อความ error/exception ในหน้า (จ) หน้าว่าง
2. **ปุ่ม/ลิงก์พิมพ์ทุกอันที่หน้านั้นมี**: ดึง URL ของรายงาน (PDF/Excel) ด้วยล็อกอินเดียวกัน ดูสถานะ HTTP, ว่าเป็น `%PDF` / xlsx จริง, ขนาดและเวลา
   ใช้ช่วงวันที่ค่าเริ่มต้นของหน้าและช่วงที่มีข้อมูล (ก.ย.–ต.ค. 2569); ตรวจ endpoint ที่ต้องรหัสพนักงาน/ลูกค้า/สินค้า/เขตการขาย/แม่พิมพ์ด้วยรหัสจริงในฐาน
3. **ปุ่มค้นหา/แสดง/พิมพ์ที่ไม่เขียนข้อมูล** กดจริงในหน้า; หน้าแก้ไขพนักงานลองค้นหา เลือก และเปิดฟอร์มจนเห็นข้อมูล
4. **Log เซิร์ฟเวอร์** (`fail:`/`crit:`) และ **console ของเบราว์เซอร์** ตลอดการตรวจ

**ไม่ได้ทำ** (ตามข้อกำหนด/ข้อจำกัด): ไม่กดปุ่มบันทึก/ลบ/คำนวณ/ปิดงวด/ตัดสต็อก/โอนผลผลิต; ไม่ได้เปิดดู PDF ทุกใบด้วยตาว่าเลย์เอาต์ตรงฟอร์มเดิม
(ตรวจเฉพาะว่าพิมพ์ออกและเป็น PDF จริง — เทียบฟอร์มเป็นงานของ UAT ลูกค้า); ไม่ได้ลองกรอกฟอร์มเพิ่ม/แก้ไขทุกช่อง; สเปคตรวจ QA ไม่มีในฐาน UAT
(เป็นข้อมูลจริงของบริษัท ไม่ถูกโหลดตาม `Reset-Uat.ps1`) หน้า QA จึงว่างโดยออกแบบ ไม่นับเป็นปัญหา
