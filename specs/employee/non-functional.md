# Non-functional — ระบบพนักงานและค่าแรง

## สิทธิ์ผู้ใช้ (NF-01)
ระบบเดิม: ไฟล์ Access เดียว ไม่มี login/สิทธิ์ ✅ ทุกคนที่เปิดไฟล์ได้ทำได้ทุกอย่าง และเห็นค่าจ้าง/เลขบัญชีทั้งหมด (`StartupShowDBWindow = True` จึงเปิดตารางตรงได้ด้วย)
การอนุมัติจ่ายเงินอยู่นอกโปรแกรม: ในเว็บธนาคารแยก "ผู้นำเข้าข้อมูล" กับ "ผู้อนุมัติ" (INT-01, INT-02) ✅

| การกระทำ | HR (ระบบเดิม) | หัวหน้าแผนก (ข้อเสนอสำหรับระบบใหม่ 🔍 ❓ Q-01) |

| ทะเบียนพนักงาน (SCR-02, SCR-03) | เพิ่ม/แก้/ลบ | ดูเฉพาะแผนกตัวเอง |
| เวลา/ไม่มาทำงาน/OT/ลา/ใบเตือน | เพิ่ม/แก้/ลบ | บันทึก |

| โบนัส / พักร้อน / ปรับค่าแรง | ทำได้ | – |
| ย้าย/ลบข้อมูล (BR-040, BR-042, BR-043) | ทำได้ | – |

## ปริมาณและประสิทธิภาพ (NF-02)
จาก `source/พนักงาน.accdb` ณ 2026-10-04:
- ผู้ใช้พร้อมกัน: 🔍 1 คน (ไฟล์บนเครื่องเดียว) ❓ Q-01
- พนักงานทำงานอยู่ 105 คน (รายเดือน 22, รายวัน 83) ทั้งหมด 443 คน
- เวลาทำงาน 1,400–1,500 แถวต่องวด, 45,000–69,000 แถวต่อปี (ADD_EW ปี 2017–2025) ประวัติสะสม 528,745 แถว
- ไม่มาทำงาน 2,600–3,450 แถวต่อปี (NO_WORK 20,260 แถว)
- การลา ~2,000 แถวต่อปี ประวัติ 42,240 แถว · ใบเตือน 44 + 301 แถว
- ประวัติค่าแรง 16,792 แถว (~2,900 แถวต่อปี = ~105 คน × 24 งวด + งวดพิเศษ)
- ขนาดไฟล์ 149 MB
- เวลาตอบสนอง: ระบบเดิมไม่มีเกณฑ์ ❓ Q-01

## รูปแบบข้อมูล (NF-03)
- วันที่: Access เก็บ Date/Time (ค.ศ. ภายใน) แสดงผลตาม locale ไทยของ Windows เป็น พ.ศ. ในหน้าจอและรายงาน ✅ (ฟิลด์ CODE เก็บข้อความวันที่ปี 2569) — รายงานบางตัวแปลงเองด้วย `ปี + 543` (BR-065, BR-070)
- timezone: ไม่มีการจัดการ ใช้เวลาเครื่องที่รัน (Asia/Bangkok 🔍)
- "วันนี้" = `Date()`/`Now()` ของเครื่องที่รัน (BR-020 อายุงาน, BR-031, BR-043, BR-053, BR-065, BR-070)
- เวลาเข้า-ออก: เก็บเป็นเวลาบนวันที่ 1899-12-30, ข้ามเที่ยงคืนเป็น 1899-12-31 — ต้องรองรับกะข้ามวัน (กะ B 20:10–05:10, กะ F 17:00–02:00)
- เงิน: บาท ทุกยอดจ่ายเป็นจำนวนเต็มบาท (การปัดเศษ RND-A/B/C ใน business-rules.md) ค่าแรงต่อวันเก็บ Double ทศนิยมสูงสุด 2 ตำแหน่ง (BR-052)
- วันลา: Single หน่วย 1/8 วัน
- ภาษาที่แสดง: ไทยทั้งหมด ยกเว้นชื่อ/คำนำหน้าอังกฤษในรายงานกสิกร
- การเรียงข้อความไทย: รายงานที่เรียงตาม DEPARTMENT ใช้การเรียงของ Access ฐานข้อมูลนี้ (Thai sort order ตาม locale) 🔍 ระบบใหม่ต้องใช้ collation ภาษาไทย เช่น `th-TH` / ICU ให้ลำดับแผนกตรงกัน · รหัสพนักงาน (ID) เป็นตัวอักษรอังกฤษ+ตัวเลข เรียงแบบข้อความ

## Audit / Backup (NF-07)
- ระบบเดิมไม่มี audit log ✅ ไม่รู้ว่าใครแก้เงินเดือน/บัญชีเมื่อไร
- สำรองข้อมูลในตัว: มาโคร `แมโคร5` และ `Macro1` คัดลอก E_WORK → E_WORK_A และ LEAVE → LEAVE_A ทุกครั้งที่ปิดหน้าจอบันทึก (สำเนาล่าสุดชุดเดียว) ✅
- backup ไฟล์: ไม่มีในโปรแกรม ❓ Q-43
- ข้อมูลส่วนบุคคล (เลขบัตร, ที่อยู่, บัญชีธนาคาร, เงินเดือน) อยู่ภายใต้ PDPA 🔍 ❓ Q-43 ระบบใหม่ต้องมี audit log การแก้เงินเดือน/บัญชีหรือไม่

## การพิมพ์ (NF-04)
- ทุกเอกสารเป็นภาษาไทย พิมพ์จาก preview ของ Access ขนาดกระดาษตามที่ตั้งในรายงาน (A4 🔍) ไม่มีเครื่องพิมพ์หรือฟอร์มสำเร็จรูปเฉพาะ 🔍
- สลิปพิมพ์ลายเซ็นจากรูปภาพ (ตาราง3.SIGN)
- เอกสารที่ต้องลงชื่อ: ค่าแรงรายคน (ผู้รับเงิน), ค่าแรงสิ้นเดือน, สรุปค่าแรง (บุคคล/ผู้จัดการโรงงาน/สมุห์บัญชี)
- ❓ Q-40 ขอตัวอย่างเอกสารจริง (ใบลา, สลิป, หนังสือรับรอง, สัญญาจ้าง) ถ้าต้องให้หน้าตาเหมือนเดิม

## การเก็บข้อมูลระยะยาว (NF-05)
- ระบบเดิมแยกตารางปัจจุบัน/ประวัติ และมีเมนูลบข้อมูลทุกปี (BR-040, BR-042) 🔍 เพราะข้อจำกัดของ Access — ✅ ข้อมูลจริงแสดงว่าไม่ได้ลบรายปีตั้งแต่ 2020 (ประวัติย้อนถึง 2016)
- ข้อเสนอสำหรับระบบใหม่: เก็บในตารางเดียว กรองด้วยวันที่ ไม่ต้องมีเมนูย้ายข้อมูล — ❓ Q-33 นโยบายการเก็บรักษาข้อมูล (retention)
- ถ้ายกเลิกการย้ายข้อมูล ต้องกำหนดรอบโควตาลาใน BR-020 ใหม่ (Q-27)
