## 1. การคำนวณเวลาและค่าแรง (ตัด WEEK)
ลำดับการทำงานเมื่อกด "คำนวณ" ในหน้าจอตั้งวันที่ตัด WEEK (มาโคร `คำนวณเวลาทำงาน` → `คำนวณค่าแรง`):
1. BR-007 ลบข้อมูลซ้ำ
2. BR-001 คำนวณ WORK_T
3. BR-002 รวมยอดต่อคน
4. BR-003 / BR-004 คำนวณเงิน
5. BR-006 บันทึกประวัติ
6. RPT ส่งธนาคาร

พารามิเตอร์: `FROM_DA` (วันเริ่มงวด), `TO_DA` (วันสิ้นงวด), `PAY_D` (วันจ่าย) และ `D = TO_DA − FROM_DA + 1` (จำนวนวันในงวด)

### BR-001 — คำนวณเวลาทำงานต่อรายการ (WORK_T)
สถานะ: ✅ · ที่มา: คิวรี `คำนวณเวลาทำงาน1`, `คำนวณเวลาทำงาน2`
ใช้กับแถว E_WORK ที่ `FROM_DA ≤ DATE ≤ TO_DA` และเขียนทับ WORK_T เดิม

`ชั่วโมง = (W_OUT − W_IN) × 24 − REST_T / 60` (ไม่ปัด)
- TYPE = `W`: `WORK_T = 1` ถ้า `ชั่วโมง/8 ≥ 0.96875` (คือ ≥ 7.75 ชม.) ไม่อย่างนั้น `WORK_T = ชั่วโมง/8` (หน่วย = วัน ไม่ปัด)
- TYPE อื่น: `WORK_T = ชั่วโมง` (หน่วย = ชั่วโมง)

| # | TYPE | W_IN–W_OUT | REST_T | WORK_T |
|---|---|---|---|---|
| 1 | W | 08:00–17:00 | 60 | 1 |
| 2 | W | 08:00–16:45 | 60 | 1 (7.75 ชม. ถึงเกณฑ์พอดี) |
| 3 | W | 08:00–16:30 | 60 | 0.9375 |
| 4 | O1 | 17:20–20:10 | 0 | 2.8333… |
| 5 | W กะ B | 20:10–05:10(+1) | 60 | 1 (W_OUT เป็นวันถัดไปใน time serial) |

⚠ กะข้ามคืนคำนวณถูกเพราะ W_OUT เก็บเป็น 1899-12-31 ถ้าผู้ใช้คีย์เวลาออก 05:10 แบบวันเดียวกัน ชั่วโมงจะติดลบ 🔍 ข้อเสนอสำหรับระบบใหม่: ควรเก็บ datetime เต็ม

### BR-002 — รวมยอดต่อพนักงานในงวด
สถานะ: ✅ · ที่มา: `คำนวณเวลาทำงาน3`–`19`, `คำนวณเวลาทำงาน13`, `คำนวณค่าแรง0/01/1`

| ตัวแปร | ความหมาย | วิธีได้มา |
|---|---|---|
| W | วันทำงานปกติ | Σ WORK_T ที่ TYPE=`W` |
| O1, S, O2, H, O3 | ชั่วโมงแต่ละประเภท | Σ WORK_T ตาม TYPE |
| L | วันลา**ได้ค่าแรง** | Σ LEAVE.SUM_D ที่ SAL=`Y` **และ FROM_D ≥ FROM_DA และ TO_D ≤ TO_DA** |
| L(NO) | วันลา**ไม่ได้ค่าแรง** | เหมือน L แต่ SAL=`N` |
| HOLI | วันหยุดประเพณีในงวดที่พนักงานมีสิทธิ์ | นับ HOLIDAY ในงวด เฉพาะวันที่ ≥ EMPLO.START และพนักงานยังไม่ลาออกหรือ RESIGN > FROM_DA |
| SUN | วันหยุดประจำสัปดาห์ในงวด | นับ SUNDAY ในงวด ให้คนที่ (RESIGN ว่าง และ START ≤ FROM_DA) หรือ RESIGN > FROM_DA ส่วนคนที่เริ่มงานกลางงวดได้ SUN = 0 ⚠ ดู BR-003 ตัวอย่าง 6 |
| SUN_DAY | วันหยุดประจำสัปดาห์ถึงวันลาออก | เฉพาะ CLAS=`1` ที่ลาออกในงวด: นับ SUNDAY ที่ ≤ RESIGN |
| DAT | วันหยุดประเพณีวันแรกในงวด | Min(HOLIDAY.DATE ในงวด) ว่างถ้าไม่มี |
| Expr1 | วันมีสิทธิ์ได้ค่าแรง | W + L |

- พนักงานที่ผลรวม W+L+S+H+HOLI+SUN = 0 จะไม่ถูกคำนวณเลย
- รหัสขึ้นต้น `LT` ถูกตัดออก (❓ Q-10)
- ⚠ การลาที่คร่อมวันตัดงวด (เช่น ลา 10–13 แต่งวดจบวันที่ 11) จะ**ไม่ถูกนับในงวดใดเลย** ❓ Q-18

ตัวอย่าง — งวด FROM_DA 27/08/2026 – TO_DA 11/09/2026 (D = 16), SUNDAY 30/08 และ 06/09, ไม่มี HOLIDAY

| # | ข้อมูลในงวด | ผล |
|---|---|---|
| 1 | E_WORK: W 13 แถว (WORK_T = 1), W 1 แถว WORK_T 0.9375, O1 2 แถว (2.8333 ชม.); LEAVE SAL=Y 1 วัน (28–28/08) | W = 13.9375, O1 = 5.6667, L = 1, L(NO) = 0, SUN = 2, HOLI = 0, Expr1 = 14.9375 |
| 2 | LEAVE SAL=N 0.5 วัน (01/09) และ SAL=Y 2 วัน (10/09–12/09 คร่อมสิ้นงวด) | L(NO) = 0.5, L = 0 (แถวคร่อมงวดไม่ถูกนับ ⚠ Q-18) |
| 3 | พนักงานเริ่มงาน 01/09/2026 (START > FROM_DA) RESIGN ว่าง | SUN = 0 (ไม่ได้วันหยุดประจำสัปดาห์ในงวดแรก) |
| 4 | พนักงานลาออก 03/09/2026 CLAS 1 | SUN = 2 (RESIGN > FROM_DA), SUN_DAY = 1 (เฉพาะ 30/08 ≤ RESIGN) |

### BR-003 — ค่าแรงปกติต่องวด (PAY_W)
สถานะ: ✅ · ที่มา: `คำนวณค่าแรง2` (รายเดือน), `คำนวณค่าแรง3`/`31` (รายวัน), `คำนวณค่าแรง4`/`41` (CLAS 3)
ผลลัพธ์ปัดด้วย RND-A ทุกกรณี

**ก. รายเดือน (CLAS=`1`)** — ตามลำดับเงื่อนไข:
1. ถ้า `POINT_1` มีค่า → `PAY_W = POINT_1`
2. ถ้ายังไม่ลาออก (`RESIGN` ว่าง):
   - ถ้า `Expr1 + HOLI ≥ D − SUN` (มาครบ) → `SALARY / 2`
   - ไม่อย่างนั้น → `(15 − L(NO)) × SA_DAY`
3. ถ้ามี `RESIGN`:
   - `Expr1 = 0` → 0
   - `RESIGN = TO_DA + 1` (ลาออกวันถัดจากสิ้นงวด) → `SALARY / 2`
   - `RESIGN > DAT` → `(Expr1 + SUN_DAY + HOLI) × SA_DAY`
   - ไม่อย่างนั้น (รวมกรณี DAT ว่าง) → `(Expr1 + SUN_DAY) × SA_DAY`

**ข. รายวัน (CLAS=`2`, HOT1=`N`)**:
1. `POINT_1` มีค่า → `POINT_1`
2. ไม่ลาออก หรือ `RESIGN > DAT` → `min(Expr1 + HOLI, D − SUN) × SA_DAY`
3. ลาออกแล้ว และ RESIGN ≤ DAT (หรือ DAT ว่าง) → `Expr1 × SA_DAY` (ไม่จ่ายวันหยุดประเพณี)

⚠ ข้อสังเกต `POINT_1`: ในฟอร์มบันทึกการประเมินผล (SCR-53) ฟิลด์นี้มีป้ายว่า "คะแนนครั้งที่ 1" ✅
ถ้า HR กรอกคะแนนประเมิน (เช่น 85) ลงไป สูตรค่าแรงจะจ่ายค่าแรงงวดนั้นเป็น 85 บาท
ปัจจุบัน POINT_1 ว่างทุกคน จึงยังไม่เกิดผล ❓ Q-09

**ค. รายวัน HOT1=`Y`**: `min(Expr1 + HOLI, D − SUN) × SA_DAY` (ไม่มีกรณี POINT_1/ลาออก) + `HOT = Round(W × 10, 2)` (RND-B)
**ง. CLAS=`3`** (❓ Q-06 ไม่มีในข้อมูล): `min(Expr1, D − SUN − HOLI) × SA_DAY` (ไม่จ่ายวันหยุดประเพณีถ้าไม่มาทำ) + HOT ถ้า HOT1=`Y`

**ตัวอย่าง** — งวด 27/08/2026–11/09/2026 (D = 16) มี SUNDAY 2 วัน (30/08, 06/09) ไม่มี HOLIDAY (HOLI = 0, DAT ว่าง) → D − SUN = 14

| # | กรณี | ข้อมูล | PAY_W |
|---|---|---|---|
| 1 | รายเดือนมาครบ | SALARY 15,000, SA_DAY 500, W=14 | 7,500 |
| 2 | รายเดือนขาด มีลาไม่ได้ค่าแรง | W=12, L=1, L(NO)=1 | (15−1)×500 = 7,000 |
| 3 | ⚠ รายเดือนขาดโดยไม่บันทึกลา | W=12, L=0, L(NO)=0 (บันทึกขาดใน NO_WORK) | (15−0)×500 = **7,500** — ขาดงานไม่ถูกหัก ❓ Q-19 |
| 4 | รายเดือน POINT_1 | POINT_1 = 8,000 | 8,000 |
| 5 | รายวันมาครบ+ลา | SA_DAY 400, W=14, L=1 | min(15,14)×400 = 5,600 |
| 6 | รายวันขาดบางวัน | W=11.5, L=1 | 12.5×400 = 5,000 |
| 7 | ⚠ รายเดือนเริ่มงานกลางงวด (SUN=0) | เริ่ม 01/09, W=8 | ต้องการ 16 วัน → ไม่ครบ → (15−0)×500 = **7,500** จ่ายเกิน? ❓ Q-20 |
| 8 | รายวัน มีวันหยุดประเพณี 1 วันในงวด | W=13, HOLI=1 | min(14,14)×400 = 5,600 |

### BR-004 — ค่าล่วงเวลาและค่าทำงานวันหยุด (PAY_OT)
สถานะ: ✅ · ที่มา: เดียวกับ BR-003
แต่ละส่วนคำนวณแล้วปัด RND-A ทีละตัว จากนั้นรวม แล้วปัด RND-A อีกครั้ง:
`ส่วน = ชั่วโมง × SA_DAY / 8 × ตัวคูณ`

| ประเภท | รายเดือน (1) | รายวัน (2) | CLAS 3 |
|---|---|---|---|
| O1 OT วันปกติ | 1.5 | 1.5 | 1.5 |
| S ทำงานวันอาทิตย์ | **1** | 2 | 2 |
| O2 OT วันอาทิตย์ | 3 | 3 | 3 |
| H ทำงานวันหยุดประเพณี | **1** | **1** | 2 |
| O3 OT วันหยุดประเพณี | 3 | 3 | 3 |

เหตุผล 🔍 รายเดือนได้ค่าจ้างวันหยุดอยู่แล้วจึงได้เพิ่มอีก 1 เท่า (ตาม พ.ร.บ.คุ้มครองแรงงาน) ⚠ รายวันทำงานวันหยุดประเพณี (H) ได้ 1 เท่า แต่วันหยุดนั้นก็ได้ค่าจ้างผ่าน HOLI อยู่แล้ว ตรงตั้งใจไหม? ❓ Q-21

ฟิลด์ที่บันทึก: `PAY_OT` = ยอดรวม, `TT_OT` = RND-A(S+O2+H+O3) ชั่วโมง (ไม่รวม O1), `OT` = ชั่วโมง O1

| # | ข้อมูล | ผล |
|---|---|---|
| 1 | รายวัน SA_DAY 400, O1 = 3.5 ชม. | 3.5×400/8×1.5 = 262.5 → **263** |
| 2 | รายเดือน SA_DAY 500, S = 8 ชม., O2 = 2 ชม. | S = 500, O2 = 2×500/8×3 = 375 → PAY_OT 875 |
| 3 | รายวัน SA_DAY 386, O1 = 2.8333 | 2.8333×386/8×1.5 = 205.06 → 205 |

### BR-005 — ใครถูกคำนวณค่าแรง
สถานะ: ✅ · ที่มา: คิวรี `คำนวณเวลาทำงาน13` (เงื่อนไข W+L+S+H+HOLI+SUN > 0 และ ID Not Like "LT*"), `คำนวณค่าแรง0`
พนักงานที่มีข้อมูลเวลาหรือลาในงวด (BR-002) ไม่ว่าจะลาออกแล้วหรือไม่ ยกเว้นรหัส `LT*`
รายงานส่งธนาคารรวมเฉพาะคนที่มีเลขบัญชี (BR-033)

### BR-006 — บันทึกผลค่าแรงและประวัติ
สถานะ: ✅ · ที่มา: `คำนวณค่าแรง5`–`83`
- ล้างตาราง `ค่าแรง` แล้วเติมผลงวดนี้: ID, NAME, W, PAY_W, TT_OT, PAY_OT, FROM_DATE, TO_DATE, HOLIDAY, SUNDAY, PAY_D, HOT, L, SA (รายเดือน = SALARY, อื่น = SA_DAY), OT
- ลบแถวใน `สำเนาของ ค่าแรง` ที่ `FROM_DATE ≥ FROM_DA` แล้วเพิ่มผลงวดนี้ → **คำนวณซ้ำได้ ผลล่าสุดทับของเดิม**
- ⚠ การลบใช้ `FROM_DATE ≥ FROM_DA` ถ้าคำนวณงวดเก่าย้อนหลัง จะลบประวัติงวดที่ใหม่กว่าทิ้งด้วย ❓ Q-22

### BR-007 — ลบข้อมูลซ้ำก่อนคำนวณ
สถานะ: ✅ · ที่มา: `ลบข้อมูลซ้ำ1`–`10`
- E_WORK: ใช้คีย์ `DATE & W_IN & TYPE & ID` ถ้าซ้ำเก็บไว้แถวเดียว (แถวไหนไม่แน่นอน)
- LEAVE: ใช้คีย์ `FROM_D & TO_D & FROM_T & ID`
- ข้อเสนอสำหรับระบบใหม่: บังคับ unique ตอนบันทึกแทน: E_WORK (DATE, ID, TYPE, W_IN), LEAVE (ID, FROM_D, TO_D, FROM_T)

### BR-008 — ตัด WEEK แบบ 2 ช่วง (ช่วงปีใหม่)
สถานะ: ✅ (สูตร) / ❓ Q-23 (เหตุผล) · ที่มา: เมนู 13–15, มาโคร `คำนวณค่าแรงช่วงที่1`, `คำนวณค่าแรงช่วงที่2`, `SLIPช่วงที่1/2`, `สรุปค่าแรงช่วงที่1/2`, `สรุปค่าแรงช่วง1+2`, `ค่าแรงส่งแบงค์ทั้ง2ช่วง`
งวดที่คร่อมปีใหม่จะคำนวณแยกเป็น 2 ช่วง:
- ช่วงที่ 1 = 27–31 ธ.ค. (ตามข้อความเมนู)
- ช่วงที่ 2 = 1–11 ม.ค.
- ผู้ใช้ตั้งวันที่ในหน้าจอ ตั้งวันที่ตัดWEEK เองทีละช่วง แล้วกด "พิมพ์เวลาทำงาน" (BR-001/002 ตามปกติ) ก่อนพิมพ์ค่าแรงของช่วงนั้น

**ความต่างจากงวดปกติ**
1. **รายเดือน (CLAS 1)** ใช้สูตร `คำนวณค่าแรง2ช่วง` แทน BR-003 ก:
   `PAY_W = RND-A( min(W + L + HOLI + SUN, DAY) × SA_DAY )`
   - `DAY` = ช่อง "จำนวนวัน" (`ตั้งวันที่ตัดWEEK.DAY`) ที่ผู้ใช้กรอกเองว่าช่วงนั้นจ่ายกี่วัน
   - ไม่มีกรณี POINT_1 หรือการลาออก
   - ค่า S และ H ใช้ตัวคูณเหมือนรายเดือนปกติ (1)
2. **รายวัน/CLAS 3** ใช้สูตรเดียวกับงวดปกติ (BR-003 ข–ง)
3. ผลเขียนลงตาราง `ค่าแรงช่วงที่1` / `ค่าแรงช่วงที่2` (แทนตาราง `ค่าแรง`) และ `ค่าแรง1ช่วงที่1/2` (เพิ่มแผนก) แล้วบันทึกประวัติ `สำเนาของ ค่าแรง` เหมือน BR-006
   - ช่วงที่ 1 ไม่เติมคอลัมน์ SUNDAY ในตาราง ค่าแรงช่วงที่1
   - คิวรี `สรุปค่าแรงช่วงที่1ปรับปรุง*` เติม SUNDAY/HOLIDAY จาก SUNDAY1/HOLIDAY1 ภายหลัง
4. ไม่สร้างตารางส่งธนาคารตอนพิมพ์ค่าแรง แต่ใช้เมนู "พิมพ์ค่าแรงส่งแบงค์ทั้ง 2 ช่วง" ซึ่งทำดังนี้:
   - รวม PAY_W, PAY_OT ของทั้งสองช่วงต่อคน (`สรุปค่าแรงช่วง1+2_4`)

### BR-021 — ค่าแรงระหว่างลา (LEAVE.PAY)
สถานะ: ✅ · ที่มา: คิวรี `ลางานได้ค่าแรง`

🔍 PAY ใช้แสดงในใบลา/รายงานเท่านั้น ค่าแรงจริงคำนวณผ่าน L ใน BR-003

🔍 สาเหตุที่ต้องย้ายคือประสิทธิภาพของ Access และเพื่อรีเซ็ตโควตาการลา ข้อเสนอสำหรับระบบใหม่: ควรเก็บในตารางเดียวแล้วกรองตามวันที่ (NF-05) แต่กฎโควตา (BR-020) ต้องระบุรอบปีให้ชัด ❓ Q-27

### BR-042 — ลบข้อมูลปีที่แล้ว
สถานะ: ✅ เมนูระบุ "ให้ลบเมื่อใช้งานถึงเดือนกุมภาพันธ์ของทุกปี" · ที่มา: ฟอร์ม `ตั้งวันที่ลบข้อมูลปีที่แล้ว` (เมนู 1.7) ปุ่ม → มาโคร `เตือนลบข้อมูล` → ฟอร์มยืนยัน `เตือนลบข้อมูลปีที่แล้ว` → มาโคร `ตั้งวันที่ลบข้อมูลปีที่แล้ว`
อินพุต `TO_DATE` → ลบแถวที่วันที่ ≤ TO_DATE จาก: ADD_EW, E_WORK, HOLIDAY, SUNDAY, NO_WORK, สำเนาของ ค่าแรง
LEAVE_ADD และ ใบเตือนADD **ไม่ถูกลบ**
ที่มา: มาโคร `ตั้งวันที่ลบข้อมูลปีที่แล้ว` (คิวรี `ตั้งวันที่ลบข้อมูลปีที่แล้ว1`–`12`: ตั้ง flag `DE`/`DEL`/`D` แล้วลบแถวที่มี flag)
🔍 ไม่ได้ถูกใช้ตั้งแต่ปี 2020: ค่า TO_DATE ที่ค้างในตารางพารามิเตอร์คือ 2019-12-26 และ ADD_EW/NO_WORK ยังมีข้อมูลตั้งแต่ปี 2016/2019
❓ Q-33 ระบบใหม่ต้องลบจริงไหม (กฎหมายแรงงานกำหนดให้เก็บเอกสารค่าจ้างอย่างน้อย 2 ปี) 🔍

### BR-043 — ลบพนักงานที่ลาออกแล้ว
สถานะ: ✅ · ที่มา: มาโคร `ลบพนักงานที่ลาออกแล้ว`
ลบ EMPLO ที่ `RESIGN ≤ วันนี้ − 1095 วัน` (3 ปี) เป็นการลบถาวร ไม่ลบข้อมูลลูก (Q-15) — เปิดจากปุ่มในฟอร์ม `EMPLO1`
ขั้นตอนจริง:
1. คิวรี `ลบพนักงานที่ลาออกแล้ว`: `UPDATE EMPLO, ตั้งวันที่พิมพ์ค่าแรงสิ้นเดือน SET MEM = "Y" WHERE RESIGN ≤ Date() − 1095`
2. คิวรี `ลบพนักงานที่ลาออกแล้ว2`: ลบทุกแถวที่ `MEM = "Y"`
3. แสดง "การลบข้อมูลพนักงานที่ลาออกเสร็จเรียบร้อยแล้ว"

- ⚠ ข้อ 1 JOIN กับตารางพารามิเตอร์ `ตั้งวันที่พิมพ์ค่าแรงสิ้นเดือน` แบบไม่มีเงื่อนไข: ถ้าตารางนั้นว่าง จะไม่มีใครถูกลบ (ปัจจุบันมี 1 แถว)
- ⚠ เหตุผลลาออกใน MEM ถูกเขียนทับเป็น "Y" ก่อนลบ และพนักงานคนใดที่ MEM = "Y" อยู่แล้วจะถูกลบด้วยแม้ยังไม่ลาออก (ปัจจุบันไม่มี)
- คิวรีสำรองข้อมูล `ลบพนักงานที่ลาออกแล้ว1` (คัดลอกเข้า `EMPLOที่ลาออกแล้ว`) มีอยู่แต่มาโครไม่ได้เรียก → ไม่มีสำเนา
- 🔍 ไม่ได้ถูกใช้มานาน: ปัจจุบันยังมีพนักงานลาออกเกิน 3 ปีค้างอยู่ 176 คน

### BR-044 — บันทึกการลาออก
สถานะ: ✅ · ที่มา: ฟอร์ม `รหัสพนักงาน2` ปุ่มบันทึก → มาโคร `บันทึกพนักงานที่ลาออก` (คิวรี `พิมพ์ใบลาออก2`) → มาโคร `พิมพ์ใบลาออก`
ฟอร์ม `รหัสพนักงาน2`: เลือกพนักงาน, วันที่ลาออก `DATE_R`, เหตุผล `RESULT` → `EMPLO.RESIGN = DATE_R`, `EMPLO.MEM = RESULT` แล้วพิมพ์ใบลาออก

## 7. รายงานสรุปค่าแรง (การคำนวณในรายงาน)

### BR-060 — สรุปค่าแรงรายแผนก (ต่องวด)
สถานะ: ✅ · ที่มา: มาโคร `สรุปค่าแรง` (เมนู 9 "ค่าแรงทั่วไป"), `สรุปค่าแรง1`
จากตาราง `ค่าแรง` (ผลงวดล่าสุด) จัดกลุ่มตาม EMPLO.DEPARTMENT:
- จำนวนคน, ΣPAY_W, ΣPAY_OT, ΣHOT
- รวม = ΣPAY_W + ΣPAY_OT + ΣHOT
- %OT = ΣPAY_OT / ΣPAY_W × 100

หัวรายงาน:
- จำนวนวันอาทิตย์ (SUNDAY1.QTY) และวันหยุด (สำเนาของ HOLIDAY1.QTY_D) ที่บันทึกไว้ตอน BR-002
- จำนวนวัน `TO−FROM+1`, วันทำงาน `TO−FROM+1−SUNDAY−HOLIDAY`, วันคิดค่าแรง `TO−FROM+1−SUNDAY`
- ค่าธรรมเนียมโอน = จำนวนรายการ × 10 บาท (รายการ = คนที่ PAY_W+PAY_OT+HOT > 0 และมี ACC)

ท้ายรายงาน: ช่องลงนาม บุคคล / ผู้จัดการโรงงาน / สมุห์บัญชี

### BR-061 — รายงานไม่มาทำงานประจำวัน (รองรับกะดึก)
สถานะ: ✅ · ที่มา: มาโคร `ไม่มาทำงาน`, ฟอร์ม `วันทำงาน1`
อินพุตวันที่ `DAT` → สร้างตาราง NO_WORK1 จากคนใน NO_WORK ที่:
- `DATE1 = DAT` และ `W_IN < 17:00` (กะกลางวัน) **หรือ**
- `DATE1 = DAT − 1` และ `W_IN > 17:00` (กะกลางคืนที่เริ่มเมื่อวาน)

แสดงชื่อ แผนก หมายเหตุ และจำนวนพนักงานทั้งหมดที่ยังทำงานอยู่
⚠ ข้อมูล NO_WORK จริงมี W_IN = 08:00 ทุกแถว เงื่อนไขกะดึกจึงไม่เคยใช้

### BR-062 — สรุปค่าแรงหลายงวด
สถานะ: ✅ · ทุกตัวอ่านจากประวัติ `สำเนาของ ค่าแรง` · ที่มา: มาโคร `รวมค่าแรง`, `สรุปค่าแรงแต่ละเดือน33333`, `ค่าแรงแต่ละเดือน`, `สรุปชั่วโมงการทำงาน`
| ฟังก์ชัน (มาโคร) | ช่วงที่เลือก | การรวม |
|---|---|---|
| รวมค่าแรง (`รวมค่าแรง` → คิวรี `รวมค่าแรง1`, `รวมค่าแรง2`) | FROM_DATE ≥ F_D และ TO_DATE ≤ T_D | **ต่อแผนก** (EMPLO.DEPARTMENT ปัจจุบันของพนักงาน ไม่ใช่แผนก ณ งวดนั้น): ΣPAY_W, ΣPAY_OT, ΣPAY_W+PAY_OT |
| สรุปค่าแรงแต่ละเดือน (`สรุปค่าแรงแต่ละเดือน33333`) | PAY_D ระหว่าง F_D–T_D | ตาราง 12 เดือน × แผนก ของ Σ(PAY_W+PAY_OT) |
| ค่าแรงแต่ละเดือน (`ค่าแรงแต่ละเดือน`, ไม่มีทางเข้า 🔍) | FROM_DATE ≥ F_D และ TO_DATE ≤ T_D | ยอดรวมของเดือนที่เลือก เก็บสะสมในตาราง `สรุปค่าแรงแต่ละเดือน` ตามช่องเดือน |
| สรุปชั่วโมงการทำงาน | FROM_DATE ≥ FROM_DAY และ TO_DATE ≤ TO_DAY, แผนกเดียว, ยังไม่ลาออก | ต่อพนักงาน: ΣW (วัน), ΣTT_OT (ชม. วันหยุด), ΣOT (ชม. O1), รวมชั่วโมง OT |

รายละเอียดของ "สรุปค่าแรงแต่ละเดือน":
- **เดือนที่ยอดเข้า** = เดือนของ PAY_D ยกเว้น PAY_D ตรงกับวันที่ 1 ให้นับเป็นเดือนก่อนหน้า (1 ม.ค. → ธ.ค.)
- **แผนก** แปลงจากตัวอักษรแรกของรหัสพนักงาน (ไม่ใช่ EMPLO.DEPARTMENT) เช่น A=ประกอบ, B=อัดผ้าเบรก, D=ไดคาสท์, F=จัดซื้อ, G=ฝนผ้าเบรก, K=ผ้าคลัทช์และดิสเบรก, M=ซ่อมบำรุง — ค่าครบทุกตัวอักษรอยู่ในคิวรี `สรุปค่าแรงแต่ละเดือน2` ใน [legacy](legacy/queries.md)
- ⚠ ตารางผลลัพธ์ชื่อ `สรุปค่าแรงแต่ละเดือน2024` แต่ใช้กับทุกปี

|---|---|---|

| 2 | 01/10/2026 | ก.ย. |

### BR-063 — ค่าแรงสิ้นเดือน / สรุปบัญชีคำนวณค่าจ้าง
สถานะ: ✅ · ที่มา: มาโคร `พิมพ์ค่าแรงสิ้นเดือน` (ปุ่ม "พิมพ์"), `พิมพ์ค่าแรงสิ้นเดือน2` (ปุ่ม "พิมพ์สรุป"), `พิมพ์ค่าแรงสิ้นเดือน3` (ปุ่ม "พิมพ์สรุป (ต้นทุน)"), `พิมพ์ค่าแรงสิ้นเดือน1`
อินพุต: F_D, T_D (MO = T_D), แผนก DEP (`*` = ทั้งหมด)
1. ดึงงวดจาก `สำเนาของ ค่าแรง` ที่ `F_D ≤ TO_DATE ≤ T_D` ของพนักงานแผนก LIKE DEP และ **GRED_1 ว่าง**
2. ค่าต่อคน:
   - อัตรา: รายเดือน = SALARY, อื่น = SA_DAY
   - จำนวนวัน: รายเดือนเว้นว่าง, อื่น = Round(ΣPAY_W / SA_DAY, 1)
   - ค่าจ้าง: รายเดือน = SALARY (⚠ ไม่ใช่ยอดที่จ่ายจริง), อื่น = ΣPAY_W
   - รวม = ΣPAY_W + ΣPAY_OT
   - แสดงเลขบัตรประชาชนด้วย
3. ตาราง `สรุปบัญชีคำนวณค่าจ้าง`: ลบแถวของแผนกนี้ แล้วเพิ่มแถวใหม่ (แผนก, จำนวนคน, Σค่าจ้าง, เดือน, Σรวม)
   → รันทีละแผนกได้หลายครั้งเพื่อสะสมเป็นสรุปทุกแผนกในหน้าเดียว
4. รายงาน `พิมพ์ค่าแรงสิ้นเดือน5` (รายคน) จากนั้นแสดงข้อความ "ตรวจสอบพนักงานที่ลาออกให้เรียบร้อย"
5. ปุ่ม "พิมพ์สรุป" → รายงาน `สรุปบัญชีคำนวณค่าจ้าง`; ปุ่ม "พิมพ์สรุป (ต้นทุน)" → VBA รันมาโคร `พิมพ์ค่าแรงสิ้นเดือน3` → รายงาน `สรุปค่าแรงประจำเดือน`
6. มาโคร `พิมพ์ค่าแรงสิ้นเดือน1` (ไม่มีทางเข้า 🔍) แบ่งแผนกด้วยตัวอักษรนำหน้ารหัส
   - ⚠ "จัดซื้อ" และ "บัญชี" ใช้ `F*` เหมือนกัน จึงนับซ้ำ

### BR-065 — ใบลา (เอกสารสรุปการลารายบุคคล)
สถานะ: ✅ · ที่มา: มาโคร `พิมพ์ใบลางาน`, ฟอร์ม `รหัสพนักงาน1`, คิวรี `พิมพ์ใบลางาน1–14`
อินพุต: รหัสพนักงาน → รายงาน `พิมพ์ใบลางาน` แสดง:
- ข้อมูลพนักงาน และปีที่เริ่มงานเป็น พ.ศ. (ปี + 543)
- วันลาสะสมแยกประเภท SR 1–16 (crosstab จาก LEAVE ปัจจุบัน) และยอดรวม
- จำนวนใบเตือนวาจา (CODE 1) และใบเตือนหนังสือ (CODE 2)
- **ข้อความสิทธิพักร้อน** (คิวรี `พิมพ์ใบลางาน14`):

| เงื่อนไข (ตามลำดับ) | ข้อความ |
|---|---|
| วันนี้ − START + 1 < 365 | ไม่มีสิทธิลาพักร้อน |
| Year(วันนี้) − Year(START) > 1 | มีสิทธิลาพักร้อน 6 วัน |
| เดือนที่เริ่มงาน = 12, 11, 10, …, 1 | 6.5, 7, 7.5, …, 12 วัน (= 6 + 0.5 × (13 − เดือน)) |

- **ข้อความสิทธิลากิจได้ค่าแรง**: อายุงาน ≥ 365 วัน → "6 วัน" ไม่อย่างนั้น "3 วัน"
  - ⚠ ขัดกับ BR-020 ที่ตรวจเพดาน 6 วันกับทุกคน
- ระหว่างทำงาน ล้างและสร้างตารางพัก `ใบเตือนด้วยวาจา` และ `วันที่สิ้นปี` ใหม่ทุกครั้ง

| # | START (วันนี้ = 04/10/2026) | สิทธิพักร้อนที่แสดง |
|---|---|---|
| 1 | 10/03/2026 | ไม่มีสิทธิลาพักร้อน (209 วัน) |
| 2 | 15/03/2025 | 2026−2025 = 1 ไม่ > 1 → เดือน 3 → 11 วัน |
| 3 | 01/01/2020 | 6 วัน |

### BR-070 — หนังสือรับรอง / เกษียณ / ปลดออก
สถานะ: ✅ · ที่มา: คิวรี `พิมพ์หนังสือรับรองเงินเดือน`, `พิมพ์หนังสือรับรองเงินเดือน1`, `เกษียณ2`, `เกษียณ3`
อินพุต: รหัสพนักงาน (หนังสือปลดออกเพิ่มเหตุผลในช่อง `เกษียณ.MARK`)

| ค่า | สูตร |
|---|---|
| อายุงาน (วัน) | Round(วันนี้ − START) (RND-B) |
| ข้อความอายุงาน | < 30 วัน → "n วัน"; ปีเต็ม ≤ 0 → "m เดือน"; เศษเดือน ≤ 0 → "y ปี"; อื่น ๆ → "y ปี m เดือน" (ปี = Int(DateDiff เดือน / 12), เดือน = DateDiff เดือน Mod 12) |
| วันเริ่มงาน/วันเกิด (ข้อความ) | "วัน เดือน(ชื่อไทย) พ.ศ. ปี+543" |
| อายุ (ปี) | Int((วันนี้ − BORN) / 365) |
| เงินเดือนในหนังสือ | รายเดือน = SALARY; อื่น ๆ = SA_DAY × 26 |
| จำนวนเงินเป็นตัวอักษร | ฟังก์ชัน `GetThaiUnit` (โมดูล ThaiNumber — กฎและตัวอย่างใน reports.md "ฟังก์ชันช่วย") ใส่ในวงเล็บ |

**ค่าชดเชย (หนังสือเกษียณ/ปลดออก)** — วันชดเชยอ่านจากตาราง `เกษียณ` คอลัมน์ 1–6:
| อายุงาน (วัน) | วันชดเชย (ค่าปัจจุบัน) |
|---|---|
| < 120 | 0 (ไม่จ่าย) |
| 120 – 364 | [1] = 30 |
| 365 – 1,094 | [2] = 90 |
| 1,095 – 2,189 | [3] = 180 |
| 2,190 – 3,649 | [4] = 240 |
| 3,650 – 7,299 | [5] = 300 |
| ≥ 7,300 | [6] = 400 |

- `ค่าชดเชย = RND-A(วันชดเชย × SA_DAY)`
- คอลัมน์ 7–13 ของตาราง `เกษียณ` เก็บข้อความอธิบายแต่ละขั้นที่พิมพ์ในหนังสือ ✅
- ⚠ ใช้ SA_DAY ทั้งรายเดือนและรายวัน (รายเดือน SA_DAY = SALARY/30) ไม่ได้คำนวณจากค่าจ้างเฉลี่ย

| # | อายุงาน, SA_DAY | ค่าชดเชย |
|---|---|---|
| 1 | 100 วัน, 400 | 0 |
| 2 | 400 วัน, 400 | 90 × 400 = 36,000 |
| 3 | 8,000 วัน, 520 | 400 × 520 = 208,000 |
